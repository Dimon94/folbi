# Folbi 奶油色作为全应用外观模式

Status: accepted

Related: #49、repo://CONTEXT.md、repo://docs/architecture/current-system-map.md

## Context

Folbi 现有外观模式只有跟随系统、浅色和深色；编辑器主题、Markdown 预览、图片面板与 Git 历史分别决定自己的内容配色。本次品牌升级选择“温暖伙伴”方向，并要求奶油色品牌皮肤可切换且覆盖全部可见内容表面，而不是只装饰空态或应用壳层。

这里存在真实取舍：独立皮肤开关会与外观模式形成组合状态；只改壳层无法满足全应用品牌一致性；统一重着色又不能破坏代码语法、Git 增删、图片像素和错误状态的语义。未来读者也会疑惑为什么奶油色模式不继续使用 Default、GitHub 或 Solarized 编辑器主题，因此需要记录边界与理由。

## Decision

### 1. 品牌皮肤由外观模式唯一持有

外观模式新增「Folbi 奶油色」。它与跟随系统、浅色、深色并列，沿用现有持久状态，不新增独立皮肤开关。默认仍为跟随系统；选择 Folbi 奶油色后固定使用浅色配色。

被否方案：增加独立皮肤开关。它会把外观模式与皮肤组合成六种状态，让持久化、测试和每个表面的投影都承担无收益的组合复杂度。被否方案：用奶油色替换浅色。它会移除现有原生浅色选择，破坏既有用户预期。

### 2. 品牌皮肤覆盖全部表面，但不重写内容语义

Folbi 奶油色覆盖应用壳层、侧栏、编辑器、Markdown 预览、图片面板、Git 历史、空态和主要按钮。代码语法、Git 增删、图片像素和错误状态保留原有语义；实现只调整承载表面与必要的对比度。

各呈现模块只读取外观模式派生出的品牌皮肤事实，不持有第二份皮肤选择。品牌皮肤不拥有根文件夹、文档、当前图片、编辑缓冲区、Git 会话状态或任何磁盘副作用。

### 3. 奶油色模式固定使用 Folbi 编辑器主题

Folbi 奶油色使用一套固定的 Folbi 编辑器主题，并暂时不显示编辑器主题选择器。用户离开奶油色后恢复原来的编辑器主题选择。

被否方案：为 Default、GitHub 和 Solarized 各增加奶油色版本。它会新增三套未被需求证明的配色组合，并削弱品牌皮肤的一致性。被否方案：只给现有浅色主题换背景。它无法保证语法颜色与奶油色表面的对比度。

## Consequences

### 正面

- 外观模式继续是唯一持久状态 owner，不产生平行真相。
- 奶油色在所有主要表面形成一致体验，同时保留内容语义。
- 用户可随时回到原生跟随系统、浅色或深色外观。

### 负面 / 成本

- Markdown 预览、图片面板和 Git 历史都需要显式接入品牌皮肤，不能只改窗口根背景。
- Folbi 编辑器主题需要单独校准语法颜色与对比度。
- SwiftUI 视觉行为缺少稳定自动化测试面，仍需真实应用 smoke 与同视口截图对比。

### 边界

- 本 ADR 冻结：品牌皮肤的状态 owner、第四种外观模式、全表面覆盖范围、语义颜色不变量，以及固定 Folbi 编辑器主题。
- 本 ADR 不裁决：品牌色的具体数值、两张空态角色图的绘制细节、AppIcon 导出参数或实现文件拆分；这些归品牌升级 spec 与实现 tickets。
- 本次不增加 Splash、独立皮肤开关、奶油色深色变体或循环动画。
- 若未来需要奶油色深色变体，或恢复奶油色下的多编辑器主题选择，应立新 ADR supersede 本记录。
